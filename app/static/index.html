HOW THE PONG DEMO WORKS

Internet → Azure Load Balancer → NGINX Ingress Controller → /pong → pong-app Service → Pong Pods.

During Demo Mode Kubernetes changes the Deployment Pod-template annotation every 3 minutes. That creates a real rolling redeployment. A new Pod is started and must pass its readiness probe before the old Pod is terminated. With maxUnavailable: 0 and maxSurge: 1, the application remains available while Pods are replaced.

The terminal never executes arbitrary shell commands. It accepts only an explicit read-only Kubernetes command whitelist. Write operations are separate API actions and require the appropriate application role.
